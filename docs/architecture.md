# Architecture

`package.json` names one default game. `npm run dev -- --game <folder>` selects another. The Vite plugin loads and validates that game's `live-patch.json` before opening ports. It serves `/api/game` with the manifest and entry URL, serves `/api/mutations` with checked source, watches the manifest's mutation folder, and publishes complete file lists on the manifest's custom event over Vite's WebSocket. Vite reconnects after disconnection; the client refetches the list on each connection. Editing the manifest restarts the development server so its validated contract stays current. A development-server restart reloads the page and resets the game run; ordinary mutation file edits preserve it.

`engine/client.ts` imports the selected game entry dynamically and calls `createGame(parent, emit)`. The game returns an adapter with `apply(action, origin)`, `removeMutation(origin)`, `snapshot()` and `destroy()`. Game-specific entity types, parameters, actions and hook names live in the game and manifest. The engine only carries generic event envelopes and action calls; nothing in `engine/` imports game code.

The mutation host reconciles each file independently. An unchanged module keeps its Worker and local state. A changed or removed module loses only its own Worker, owned entities and parameter writes. `onStart` runs once for a new or changed file. Source validation parses JavaScript and rejects oversize files, imports and free references to forbidden identifiers before loading. Each Worker reports its exported hooks at load time; the host sends only matching events. Pending ticks accrue into the next tick delta. A full queue drops its oldest event and counts it instead of disabling the module.

Each module has an opaque-origin iframe with `allow-scripts` and a restrictive CSP (`default-src 'none'`, `connect-src 'none'`). The module itself runs in a blob Worker created by that frame. It has no DOM, frame navigation or sibling frames; Worker creation and `importScripts` are removed from its global scope. A private `MessagePort` carries hook results, so a module cannot spoof messages to the host through the Worker's global `postMessage`. The frame accepts `load` only once and only from its parent. The host validates all messages and game actions. A 1.5 second load deadline and 200 ms event deadline disable a stalled Worker while the Phaser scene continues. Async hook rejections and unhandled Worker errors disable the module. The host clamps numeric action values, truncates long strings, drops invalid values and applies at most 20 actions per hook and 60 per second. Repeated invalid output disables a module. Per-kind entity caps further limit runaway effects.

The Arena Survivor adapter uses a Phaser scene with player movement, Space attacks, entities with stable IDs, timed despawn, score and lives. It emits player, spawn, score, hit and entity-contact events. The scene validates every action again, including kinds, numbers, limits, colors and text. A new run clears the swarm and resets run time, while total elapsed time remains available for timed mutations.

`npm test` and `npm run smoke` copy the active game into a temporary folder and choose a free port. All fixture mutations go into that copy, so tests may run while the live development game remains open. The game's own `tests/smoke/` suite checks five seconds of play with each example, frame gaps, baseline-relative rate, finite state, error isolation, hot reload and ownership behavior.

This browser isolation is one layer. The Phase 3 runner still needs its own worktree, filesystem path gate, sandboxed process, no network, and a passing dynamic smoke test before a generated patch reaches the live game.
