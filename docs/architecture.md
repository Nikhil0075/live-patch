# Architecture

`package.json` names one default game. `npm run dev -- --game <folder>` selects another. The Vite plugin loads and validates that game's `live-patch.json` before opening ports. It serves `/api/game` with the manifest and entry URL, serves `/api/mutations` with checked source, watches the manifest's mutation folder, and publishes complete file lists on the manifest's custom event over Vite's WebSocket. Vite reconnects after disconnection; the client refetches the list on each connection. Editing the manifest restarts the development server so its validated contract stays current. A development-server restart reloads the page and resets the game run; ordinary mutation file edits preserve it.

`engine/client.ts` imports the selected game entry dynamically and calls `createGame(parent, emit)`. The game returns an adapter with `apply(action, origin)`, `removeMutation(origin)`, `snapshot()` and `destroy()`. Game-specific entity types, parameters, actions and hook names live in the game and manifest. The engine only carries generic event envelopes and action calls; nothing in `engine/` imports game code.

The mutation host reconciles each file independently. An unchanged module keeps its Worker and local state. A changed or removed module loses only its own Worker, owned entities and parameter writes. `onStart` runs once for a new or changed file. Source validation parses JavaScript and rejects oversize files, imports and free references to forbidden identifiers before loading. Each Worker reports its exported hooks at load time; the host sends only matching events. Pending ticks accrue into the next tick delta. A full queue drops its oldest event and counts it instead of disabling the module.

Each module has an opaque-origin iframe with `allow-scripts` and a restrictive CSP (`default-src 'none'`, `connect-src 'none'`). The module itself runs in a blob Worker created by that frame. It has no DOM, frame navigation or sibling frames; Worker creation and `importScripts` are removed from its global scope. A private `MessagePort` carries hook results, so a module cannot spoof messages to the host through the Worker's global `postMessage`. The frame accepts `load` only once and only from its parent. The host validates all messages and game actions. A 1.5 second load deadline and 200 ms event deadline disable a stalled Worker while the Phaser scene continues. Async hook rejections and unhandled Worker errors disable the module. The host clamps numeric action values, truncates long strings, drops invalid values and applies at most 20 actions per hook and 60 per second. Repeated invalid output disables a module. Per-kind entity caps further limit runaway effects.

The Arena Survivor adapter uses a Phaser scene with player movement, Space attacks, entities with stable IDs, timed despawn, score and lives. It emits player, spawn, score, hit and entity-contact events. The scene validates every action again, including kinds, numbers, limits, colors and text. A new run clears the swarm and resets run time, while total elapsed time remains available for timed mutations.

Phase 2 attaches a local Twitch service to Vite's development HTTPS server, using a self-signed certificate for local development. The OAuth code flow authorizes broadcaster and bot accounts separately, checks state and scopes, validates tokens at startup and hourly, and refreshes them after expiry or a 401 response. Transient validation failures leave an active chat socket running and schedule a retry; successful validation starts EventSub if it was offline. Typed credential errors stop EventSub when Twitch rejects a token; transient failures retry. Tokens are stored outside Git in `.live-patch/tokens.json`, and Vite denies requests for that directory and any `tokens.json` or `ideas.json` file. EventSub uses separate WebSocket sessions because Twitch rejects subscriptions created by different users on one session: the bot subscribes to chat and the broadcaster subscribes to configured custom-reward redemptions. Chat stays active if the reward subscription fails; its failure is shown separately. Each socket handles keepalives, Twitch reconnect handoff and dropped-socket retries. A rejected subscription (4xx except 429) keeps its error visible and waits for a configuration or authorization change; network, rate-limit and server failures retry. EventSub message IDs are deduplicated before the shared typed-event pipeline ingests them; local simulator events use that same pipeline.

The shared chat pipeline parses commands and updates an atomic JSON idea store in `.live-patch/ideas.json`. It enforces a 200-character idea limit, a three-minute per-viewer cooldown, one vote per viewer, and moderator or broadcaster checks for `!approve`, `!reject` and `!rollback`. Denied moderator commands are silent, and other error replies are limited to one per viewer per 30 seconds. The bot sends acknowledgements through Twitch's Send Chat Message API; simulator replies stay local. Ordinary viewer chat reaches the browser as a Vite custom event and becomes the game's `onChat` event; bot replies and recognized control commands do not. `/simulator.html` renders viewer content with `textContent` and labels only the current pending candidates with their command numbers. Its event POST endpoint accepts local JSON requests when enabled. Phase 3 consumes approved ideas and rollback requests; Phase 4 adds scheduled voting and stream overlays.

The Phase 3 runner serializes approved ideas, creates a dedicated Git worktree and branch for each run, snapshots the active game, strips builder instruction files and project Codex settings, then prompts the Codex TypeScript SDK using the active manifest's API docs, examples, mutation path and test command. The SDK pins `workspace-write`, native Windows elevated sandbox mode, no additional writable roots, disabled shell, apps, plugins, tool network and web search, a restricted environment and a three-minute abort. The runner enumerates configured MCP servers, overrides each to disabled and checks the effective list. Before the first model turn, a direct sandbox probe confirms that writing inside the worktree succeeds and writing in the main repository fails; a failed probe rejects the run. The runner accepts only one new, regular mutation file under the manifest directory. It applies the engine source gate, gives one repair turn on failure, and runs the manifest smoke command against an isolated copy with every active module plus the candidate before committing the worktree change and atomically publishing the file to the live game. Rejected or crashing output never reaches the live mutation directory. Run records in `.live-patch/runs.json` hold the Codex thread ID, branch, commit, outcome and duration; `/api/runs` and the `live-patch:runner` event expose redacted progress. Failed branches are deleted. Rollback interrupts an active build, cancels queued approvals, removes the latest shipped file immediately, then reverts its patch commit. Startup reconciles interrupted builds, removes a half-published candidate and prunes stale worktrees. The simulator shows recent run results as plain text.
Twitch chat delivery is checked using the response body as well as the HTTP status. A dropped bot message becomes a visible connection warning in the simulator while idea ingestion remains available.

`npm test` and `npm run smoke` copy the active game into a temporary folder, choose a free port and isolate the idea store. All fixture mutations go into that copy, so tests may run while the live development game remains open. The game's own `tests/smoke/` suite checks five seconds of play with each example, frame gaps, baseline-relative rate, finite state, error isolation, hot reload, ownership and the simulator-to-game chat path. Unit tests cover command permissions, store behavior, OAuth, event normalization and WebSocket reconnects.

The browser mutation sandbox and runner worktree are separate layers. The runner's static gates and dynamic smoke test must pass before a generated patch reaches the live game.

Phase 4 adds `RoundCoordinator` in `engine/pipeline/rounds.ts`. It persists the current pitch, vote, approval or build phase in `.live-patch/rounds.json`; pitch and vote deadlines are 60 and 45 seconds. At the pitch deadline it fixes at most three candidate IDs, so late ideas cannot change vote numbers. The existing one-vote-per-viewer store still counts votes. Immediate triage rejects explicit unsafe requests, merges exact duplicate pitches and tracks contributors. An operator-triggered `CodexTriage` call can refine or merge pitches during the pitch window; it has no shell, web, apps, plugins or MCP tools and its returned IDs are checked against the pending set. Failure leaves immediate triage results intact.

The Vite server exposes read-only round and saved-build summaries and accepts same-origin JSON control actions for pause, resume, advance, approval, rejection, rollback and save. Twitch chat permissions remain in the shared command pipeline; the local control page acts as the operator. `overlay.html` is a transparent OBS Browser Source over a separate game-window capture, and `control.html` shows the same state and controls. Both render viewer data with `textContent`. `engine/overlay/builds.ts` copies the selected game into an ignored `builds/<id>/game` snapshot, omits hidden and local data, includes shipped mutation files and writes patch notes with contributor credit.
