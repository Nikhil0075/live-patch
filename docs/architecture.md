# Architecture

`package.json` names one default game. `npm run dev -- --game <folder>` selects another. The Vite plugin loads and validates that game's `live-patch.json` before opening ports. It serves `/api/game` with the manifest and entry URL, serves `/api/mutations` with checked source, watches the manifest's mutation folder, and publishes complete file lists on the manifest's custom event over Vite's WebSocket. Vite reconnects after disconnection; the client refetches the list on each connection. Editing the manifest restarts the development server so its validated contract stays current. A development-server restart reloads the page and resets the game run; ordinary mutation file edits preserve it.

`engine/client.ts` imports the selected game entry dynamically and calls `createGame(parent, emit)`. The game returns an adapter with `apply(action, origin)`, `removeMutation(origin)`, `snapshot()` and `destroy()`. Game-specific entity types, parameters, actions and hook names live in the game and manifest. The engine only carries generic event envelopes and action calls; nothing in `engine/` imports game code.

The mutation host reconciles each file independently. An unchanged module keeps its Worker and local state. A changed or removed module loses only its own Worker, owned entities and parameter writes. `onStart` runs once for a new or changed file. Source validation parses JavaScript and rejects oversize files, imports and free references to forbidden identifiers before loading. Each Worker reports its exported hooks at load time; the host sends only matching events in ordered batches of up to 16. Pending ticks accrue into the next tick delta. A full queue drops its oldest event and counts it instead of disabling the module.

Each module has an opaque-origin iframe with `allow-scripts` and a restrictive CSP (`default-src 'none'`, `connect-src 'none'`). The module itself runs in a blob Worker created by that frame. It has no DOM, frame navigation or sibling frames; Worker creation and `importScripts` are removed from its global scope. A private `MessagePort` carries hook results, so a module cannot spoof messages to the host through the Worker's global `postMessage`. The frame accepts `load` only once and only from its parent. The host validates all messages and game actions. A 1.5 second load deadline and an event deadline scaled from 1.8 seconds for one event to at most 2.2 seconds for a batch of 16 disable a stalled Worker while the Phaser scene continues. Async hook rejections and unhandled Worker errors disable the module. The host clamps numeric action values, truncates long strings, drops invalid values and applies at most 20 actions per event batch and 60 per second. Repeated invalid output disables a module. Per-kind entity caps further limit runaway effects.

The Arena Survivor adapter uses a Phaser scene with player movement, Space attacks, entities with stable IDs, timed despawn, score and lives. It emits player, spawn, score, hit and entity-contact events. The scene validates every action again, including kinds, numbers, limits, colors and text. A new run clears the swarm and resets run time, while total elapsed time remains available for timed mutations.

Phase 2 attaches a local Twitch service to Vite's development HTTPS server, using a self-signed certificate for local development. The OAuth code flow authorizes broadcaster and bot accounts separately, checks state and scopes, validates tokens at startup and hourly, and refreshes them after expiry or a 401 response. Transient validation failures leave an active chat socket running and schedule a retry; successful validation starts EventSub if it was offline. Typed credential errors stop EventSub when Twitch rejects a token; transient failures retry. Tokens are stored outside Git in `.live-patch/tokens.json`, and Vite denies requests for that directory and any `tokens.json` or `ideas.json` file. EventSub uses separate WebSocket sessions because Twitch rejects subscriptions created by different users on one session: the bot subscribes to chat and the broadcaster subscribes to configured custom-reward redemptions. Chat stays active if the reward subscription fails; its failure is shown separately. Each socket handles keepalives, Twitch reconnect handoff and dropped-socket retries. A rejected subscription (4xx except 429) keeps its error visible and waits for a configuration or authorization change; network, rate-limit and server failures retry. EventSub message IDs are deduplicated before the shared typed-event pipeline ingests them; local simulator events use that same pipeline.

The shared chat pipeline parses commands and updates an atomic JSON idea store in `.live-patch/ideas.json`. It enforces a 200-character idea limit, a three-minute per-viewer cooldown, one vote per viewer, and moderator or broadcaster checks for `!approve`, `!reject` and `!rollback`. Denied moderator commands are silent, and other error replies are limited to one per viewer per 30 seconds. The bot sends acknowledgements through Twitch's Send Chat Message API; simulator replies stay local. Ordinary viewer chat reaches the browser as a Vite custom event and becomes the game's `onChat` event; bot replies and recognized control commands do not. The Practice view renders viewer content with `textContent` and labels only the current pending candidates with their command numbers. Its event POST endpoint accepts local JSON requests when enabled. Phase 3 consumes approved ideas and rollback requests; Phase 4 adds scheduled voting and stream overlays.

The Phase 3 runner serializes approved ideas, creates a dedicated Git worktree and branch for each run, snapshots the active game, strips builder instruction files and project Codex settings, then prompts the Codex TypeScript SDK using the active manifest's API docs, examples, mutation path and test command. The SDK pins `workspace-write`, native Windows elevated sandbox mode, no additional writable roots, disabled shell, apps, plugins, tool network and web search, a restricted environment and a three-minute abort. The runner enumerates configured MCP servers, overrides each to disabled and checks the effective list. Before the first model turn, a direct sandbox probe confirms that writing inside the worktree succeeds and writing in the main repository fails; a failed probe rejects the run. The runner accepts only one new, regular mutation file under the manifest directory. It applies the engine source gate, gives one repair turn on failure, and runs the manifest smoke command against an isolated copy with every active module plus the candidate before committing the worktree change and atomically publishing the file to the live game. Rejected or crashing output never reaches the live mutation directory. Run records in `.live-patch/runs.json` hold the Codex thread ID, branch, commit, outcome and duration; `/api/runs` and the `live-patch:runner` event expose redacted progress. Failed branches are deleted. Rollback interrupts an active build, cancels queued approvals, removes the latest shipped file immediately, then reverts its patch commit. Startup reconciles interrupted builds, removes a half-published candidate and prunes stale worktrees. The simulator shows recent run results as plain text.
Twitch chat delivery is checked using the response body as well as the HTTP status. A dropped bot message becomes a visible connection warning in the simulator while idea ingestion remains available.

`npm test` and `npm run smoke` copy the active game into a temporary folder, choose a free port and isolate the idea store. All fixture mutations go into that copy, so tests may run while the live development game remains open. `npm test` also runs a real HTTPS/HTTP2 server with Chromium to check Practice and Go Live mutations; the same-origin guard accepts HTTP/1.1 `Host` or HTTP/2 `:authority` and still rejects other origins. The game's own `tests/smoke/` suite checks five seconds of play with each example, frame gaps, baseline-relative rate, finite state, error isolation, hot reload, ownership and the simulator-to-game chat path. Unit tests cover command permissions, store behavior, OAuth, event normalization and WebSocket reconnects.

The browser mutation sandbox and runner worktree are separate layers. The runner's static gates and dynamic smoke test must pass before a generated patch reaches the live game.

Arena Survivor shares a 64-particle visual budget across built-in hits and mutation bursts. At most four bursts start in one game frame, with smaller later bursts; the renderer draws circles in one color-grouped pass without per-particle glow strokes. The isolated test server skips Setup's startup process checks, while a normal operator server warms them for the first wizard visit.

Phase 4 adds `RoundCoordinator` in `engine/pipeline/rounds.ts`. It persists the current pitch, vote, approval or build phase in `.live-patch/rounds.json`; pitch and vote deadlines are 60 and 45 seconds. At the pitch deadline it fixes at most three oldest pending candidate IDs and clears their votes. Unselected pitches remain queued; losing candidates become `lost_vote` when the next round starts. The existing one-vote-per-viewer store still counts votes. Immediate triage rejects explicit unsafe requests, merges exact duplicate pitches and tracks contributors. An operator-triggered `CodexTriage` call proposes refinements and merges during the pitch window; proposals are validated and stored as a preview, then explicitly applied or discarded by the operator. Its model has no shell, web, apps, plugins or MCP tools. Failure leaves immediate triage results intact. The approved specification is the runner's build task, with the original pitch included only as context.

The Vite server exposes read-only round, saved-build and recent runner-event summaries and accepts same-origin JSON control actions for pause, resume, advance, triage preview/apply/discard, build cancellation, approval, rejection, rollback and save. Twitch chat permissions remain in the shared command pipeline; the local control page acts as the operator. `overlay.html` is a transparent OBS Browser Source over a separate game-window capture, and `control.html` shows the same state and controls. Both render viewer data with `textContent`. The overlay derives shipped-patch credit from run records and idea contributors, and shows recent redacted file and smoke-test events. `engine/overlay/builds.ts` copies the selected game into an ignored `builds/<id>/game` snapshot, omits hidden and local data, includes shipped mutation files and writes Markdown-escaped patch notes with contributor credit. Saved snapshots are play-only; the runner refuses builds from a `builds/` game folder before creating a worktree.

Phase 4.5 mounts the streamer studio in `engine/app.ts` at `/`: Home and game play, Library, Go Live, Builds, Setup, Settings and Practice share one full-height rail and design system. The old control and simulator URLs redirect to these views. Go Live has a three-column stream dashboard with a mirror of the real Play window, ballot, Codex timeline, patches and recent chat. The preview runs only while the Play window is open and does not create a second game. `/overlay.html` remains a separate transparent, silent page with a 1920×1080 layout scaled as a unit to the OBS source. All viewer text is inserted as text nodes. `engine/manifest/library.ts` discovers manifests in `games/` and imported folders, returns manifest capabilities for the Library details panel, validates local imports, runs the manifest smoke command and records its result. The UI shows that command and asks for confirmation before import. `scripts/new-game.mjs` creates a minimal playable game and example; ignored `active-game.json` under `LIVE_PATCH_DATA_DIR` records the Library selection. Switching restarts Vite and binds the runner to the selected manifest. Saved builds are listed with plain-text patch notes; play-only opening uses a temporary process selection and shows a return action, leaving the saved active-game choice intact.

`engine/studio/setup.ts` checks local requirements, Codex sign-in, the Windows sandbox probe, project path and read-only Defender Controlled Folder Access status. It reads Codex login status from both stdout and stderr. The first-run Setup wizard shows six navigable steps, loading rows, item-level actions and a self-test. Before elevation, it captures the launching account and Codex home, then passes `--user` and `--codex-home` to the elevated setup process after an operator click; it does not edit Windows security policy. Expensive setup checks start in the background when the server starts and are cached for 30 seconds, with an origin-checked POST for refresh. `engine/studio/credentials.ts` writes selected Twitch fields to `.env` atomically and presents only a set/not-set marker for the secret. Vite's env loader is disabled so this file change does not restart the dev server; the app loads its own `.env` and the same-origin JSON endpoint reloads auth and EventSub in process, updates the reward ID, and can remove credentials and tokens. `engine/studio/settings.ts` persists timing, sound and overlay settings in ignored, Vite-denied `.live-patch/settings.json`. `RoundCoordinator` adopts timing changes for future round transitions. The arena's `audio.ts` synthesizes all effects and music in the play view after a user gesture. `art.ts` draws gradients, glows and faces into original canvas textures used by Phaser images. Arena Survivor's Library cover is an original generated illustration. Games without a cover receive a deterministic SVG from `engine/manifest/cover-art.ts`. The mutation host uses `effect-limits.ts` to enforce declared effect names and rolling per-module and global limits before applying actions.

On a normal first visit, Home redirects to Setup until the operator completes or skips the wizard. The isolated browser smoke harness suppresses this redirect so game tests can load Home directly.

Phase 5 adds `scripts/setup.mjs` as a fresh-clone command and moves browser-safe settings defaults into `engine/studio/settings-defaults.ts`. The Practice form uses distinct simulated viewers for generated pitches and votes. `engine/twitch/rewards.ts` reads the reward's current availability and can create an app-owned text reward; `engine/twitch/refunds.ts` persists reward fulfillment and refund attempts. After an accepted idea is stored, the app marks its own reward redemption fulfilled; rejected app-owned, unfulfilled redemptions can be canceled for a refund. `engine/twitch/predictions.ts` persists Twitch Channel Points Prediction IDs and outcomes, serializes settlement calls, and reconciles unfinished predictions after restart. The operator starts a prediction during approval; shipped patches settle Ships and patch-gate or smoke failures settle Fails. Infrastructure failures, rejection, cancellation and interrupted builds cancel the prediction. The broadcaster OAuth token now requires redemption management and prediction management scopes. All new data files remain under the ignored, Vite-denied data directory.

`engine/pipeline/rollback-votes.ts` persists one vote per viewer for a two-minute advisory ballot on the latest shipped run. The chat command `!rollbackvote` opens and fills the ballot; three votes prompt moderator attention. A Twitch moderator or broadcaster can use `!rollback` immediately with zero votes, as can the local operator control. The Arena Survivor adapter records mutation edits to other entities and score credit for the current run so `removeMutation` can reverse those effects where game state still exists. It does not resurrect removed hostile entities at rollback. The saved-build writer bundles the game entry into a self-contained browser module before publishing the snapshot. `/compare.html` opens original and evolved playback views from that snapshot, with no live mutation or chat feed. Its game manifest and mutation list come from read-only comparison endpoints.

During a live build, Git and Codex MCP discovery use asynchronous child processes so their waits do not block the studio HTTP server. Startup recovery still finishes synchronously before accepting new builds. An opt-in browser test asserts WebGL rendering and exercises the crowded Space attack; routine headless tests remain unchanged. The WebGL probe exposed patch timeouts with Phaser player postprocessing. The arena now uses its generated shaded textures without those GPU passes.
## Phase 5.5 play shell

`engine/app.ts` serves the studio at `/` and the game in a named `/play` window. It checks Codex and OBS status on every studio view. `engine/play-menu.ts` owns the pause menu, full screen and persistent sound/accessibility controls; Back to studio focuses the opener while keeping Play paused. The optional manifest `controls` array supplies a read-only key map. `GameAdapter.pause/resume` freezes game time and audio, while `MutationHost.setPaused` stops event delivery and discards deferred actions from removed modules; the server's chat round continues. `docs/play-layout.md` records the 1920 × 1080 play and overlay zones. The OBS editor marks and warns on HUD and toast keep-clear regions.

The Practice demo is a manifest-declared prepared module. `engine/twitch/practice-demo.ts` requires an all-Practice approval ballot and no live chat connection. Its idea status is `demo`, distinct from a viewer patch that actually shipped. Each new demo replaces the previous active demo file and marks its earlier run rolled back. Go Live can remove active demo modules before a stream; generated `demo-*.js` files are Git-ignored. The Play window reads run and mutation metadata for a named ship toast, including a recent ship that occurred before the window opened.
## Phase 5.5 Practice demo

Practice pitches are marked in `IdeaStore` when they arrive from the simulator. `/api/practice/demo` requires a same-origin JSON request, an approval-stage Practice candidate and a manifest-declared `demoMutation`; it validates the prepared source, reads its literal `meta.title`, and atomically copies it into the active mutation folder. The title is saved on the demo run for its Practice reply, runner event and OBS overlay. A demo run can be rolled back without a Git revert and is excluded from the Twitch pitch path. The auto-round UI sends three pitches and votes through the same simulator pipeline used by manual Practice.
## Phase 5.5 stream dashboard

The `/play` client publishes one low-rate game canvas bitmap per second on a same-origin `BroadcastChannel`. Go Live draws it in a preview canvas and composites the separate OBS overlay document over it; no second game adapter is constructed. Dashboard panels use two persisted layout presets and browser-local collapse/order state. Their Activity feed derives entries from actual ideas, runner events, refunds, predictions and saved builds.
## Phase 5.5 library and overlay

`engine/manifest/library.ts` exposes manifest controls and whether a game was imported. Library filters and sorting use only real catalog data. The stream overlay keeps patch chips below the Play HUD, a Codex card on the right, the ballot above the bottom edge and a pitch ticker to the right of the fading key hint. Viewer text is always appended through `textContent`.

The game canvas and drawn floor are now 1152 × 648, matching a 16:9 Play window and 1920 × 1080 OBS capture without side bars. The Go Live preview receives a 480 × 270 snapshot of the actual renderer. `engine/overlay/layout-editor.ts` provides add, remove, drag, resize and exact coordinates for OBS widgets; `SettingsStore` bounds and persists the layout. `engine/studio/overlay-placement.ts` sets widget-specific minimums and moves effective widget positions out of the HUD and patch-toast zones; a ballot under 800 px wide uses stacked rows and a taller minimum. The separate overlay page polls these settings, so an OBS browser source updates without restarting or mounting a game.

Before an approval and again at the start of a real build, `scripts/probe-browser.mjs` launches Chromium in the same test-server environment as smoke. Setup reports that launch result. The runner retries one browser-launch failure, keeps full smoke diagnostics in the local run record, and exposes only safe failure wording to the studio and overlay. Smoke's `testing` event means started; `passed` alone marks its timeline step complete. The module host retains a finite 1.8–2.2 second event-batch deadline to tolerate scheduler stalls during simultaneous game, Codex and smoke processes.
